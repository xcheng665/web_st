# 面向建筑设计规范合规审查的可追溯知识图谱框架：融合大语言模型与人工审核

**作者：** [待填写]  
**研究方向：** 工程信息化、BIM 与建筑规范自动审查  
**稿件状态：** 中文初稿；参考文献及全部数值实验结果尚待核验。

## 摘要

建筑设计规范合规审查是一项典型的知识密集型任务。规范要求分布于不同条文之中，其适用性常受建筑使用性质、高度、抗震设防烈度、火灾危险性、构件类型及例外规定等因素共同影响，并同时包含定性义务与定量阈值。传统关键词检索和规则系统的语义覆盖有限，而直接使用大语言模型（Large Language Model，LLM）抽取规范知识，可能生成缺乏原文支持或无法审计的结论。为此，本文提出一种面向建筑设计规范的可追溯知识图谱与合规审查框架，融合受证据约束的 LLM 知识抽取、人工审核、知识图谱构建及基于规则的项目审查。该框架要求每一项实体、关系和规则抽取结果均关联其来源条文中的连续原文片段；未经审核的 LLM 输出仅以可追溯候选标注形式保存，不直接写入知识图谱。项目审查层将设计参数与已审核规则关联，并输出通过、不满足、待确认和提示四类结果。实验方案基于中国建筑防火与抗震设计规范构建人工裁决语料，并结合独立审核的合规案例集，对比模式规则基线、无证据约束的 JSON 抽取及本文方法，采用抽取 F1 值、证据可定位率、审查准确率、宏平均 F1 值和不当确定性率进行评价。**[此处补入已核验实验结果及置信区间。]** 本文的贡献在于建立以规范原文证据为中心的知识抽取与审查流程，以降低无依据的规范性断言，并使自动化审查输出能够被工程专业人员复核。

**关键词：** 建筑规范合规审查；知识图谱；大语言模型；信息抽取；可追溯性；建筑信息模型。

## 1 引言

建筑设计合规审查是工程建设过程中的长期瓶颈。一项设计决策往往受到多条规范条文约束，而条文含义又取决于建筑使用性质、建筑高度、抗震设防烈度、消防风险、建筑部位以及其他条文中的例外条件。在实际工作中，工程人员需要定位适用条文，将其中的约束转化为项目条件，并为每一项审查结论保留可辩护的依据。该过程具有重复性，却无法被简单的文本检索安全替代，因为适用条件与数值要求同样重要。**[CIT-AEC-COMPLIANCE]**

知识图谱已被用于连接建筑对象、法规规范和设计数据。在规范审查场景中，知识图谱的价值不仅在于建立概念关联，更在于使其中的知识事实能够追溯至权威来源，并能够接受语义层面的验证。然而，完全依赖人工构建图谱成本较高；自动抽取的图谱则可能继承抽取错误，或者遗漏决定条文适用范围的上下文限定。**[CIT-KG-AEC] [CIT-RULE-CHECKING]**

大语言模型为结构化处理长篇规范文本提供了新的可能。它能够从难以由人工规则完全覆盖的条文中识别候选实体，并形成候选关系和规则表达。但是，LLM 流畅的输出也在规范领域引入了特殊风险：看似合理的陈述可能并未被当前条文支持。可靠的工程工作流应当区分“模型候选抽取”与“经审核的知识断言”，保存其原始文本证据，并在项目输入或规则上下文不完整时拒绝给出二元化结论。**[CIT-LLM-REGULATION] [CIT-EXPLAINABLE-AI]**

针对上述问题，本文提出一种可追溯的建筑规范知识抽取与合规审查框架。本文并不将 LLM 定位为独立的合规判断主体，而是将其用于生成带有证据约束的结构化候选标注，并在候选信息进入知识图谱前实施人工审核。由此形成的知识图谱能够支持项目审查：每项审查结论均可链接至已审核规则，并在适用时进一步回溯至其来源条文。本文围绕以下研究问题展开：

1. 受证据约束的抽取机制能否提高规范知识抽取的可靠性与可审计性？
2. 人工审核对图谱断言质量和修正工作量有何影响？
3. 基于“项目参数—规则—条文”链路的审查机制，能否产生具有适当不确定性表达的合规结论？

本文的主要贡献包括：第一，构建涵盖建筑对象、条件、数值、关系、约束、来源条文及审核状态的轻量级本体；第二，提出针对每个 LLM 抽取断言保留连续条文证据的约束机制；第三，将待审核、审核中、接受和拒绝等状态纳入知识治理过程，避免将模型输出误认为已确认的规范知识；第四，提出可复现实验协议，用于评估抽取质量、证据可定位性和不确定性感知的项目审查能力。

## 2 相关工作

### 2.1 建筑规范自动合规审查

既有自动合规审查研究通常将 BIM 数据、规则语言和领域本体结合，用于验证特定的规范要求。这类方法在规则已被完整形式化时可以取得较高精度，但同时依赖成本较高的规则工程；对于适用条件隐含、分散于不同条文或依赖上下文的文本规则，仍存在处理困难。最终稿将围绕规范检索、规则形式化和端到端审查三个层面，与本文方法进行比较。**[CIT-BIM-RULE-1] [CIT-BIM-RULE-2]**

### 2.2 建成环境领域知识图谱

建筑领域知识图谱用于建模设计、施工和运维过程中的概念及其关系。对于规范审查而言，来源溯源是不可缺少的属性：若一条图谱边无法定位到具体规范条文，就无法为规范性判断提供可审计基础。因此，本文将条文证据与审核状态作为图谱事实的一等属性，而不是仅作为界面展示信息。**[CIT-KG-PROVENANCE]**

### 2.3 基于 LLM 的信息抽取与可信人工智能

近期研究表明，LLM 在结构化信息抽取中具有较强潜力，但其输出也会受到提示词、模型版本和源文本歧义的影响。在高风险或高责任领域，以证据为基础的生成和人在回路审核常被视为重要保障。本文在建筑规范条文这一更具体的情境中检验上述机制，并同时报告语义抽取指标与证据层面指标。**[CIT-LLM-IE] [CIT-HUMAN-LOOP]**

## 3 可追溯知识图谱与合规审查框架

### 3.1 总体框架

该框架由五个阶段组成：（1）规范导入与条文切分；（2）候选知识抽取；（3）证据验证与人工审核；（4）知识图谱构建；（5）项目合规审查。系统当前支持将 CSV、电子表格、PDF 和 Word 文档导入 SQLite 支撑的规范库。现有语料包含 5 部中国建筑规范和 962 条已导入条文。主实验语料由 GB50016 建筑设计防火规范条文与 GB50011 建筑抗震设计规范条文构成，其余规范用于预实验和可迁移性分析。

### 3.2 本体与证据约束

本体包括建筑对象、建筑部位、性能指标、数值、标准、行为和适用条件等实体类型；关系包括适用于、具有属性、要求、禁止、上下限、比较和包含等类型。一条规则记录其规则名称、适用条件、约束主体、运算符、阈值或要求、来源标准、条文号、证据片段及审核状态。

对于每一项输出，证据必须是其来源条文中的非空连续子串。若候选证据无法被精确定位，该项输出将被拒绝或退回修改。该约束并不能完全保证语义解释正确，但可以防止候选知识断言脱离其规范来源。

### 3.3 候选抽取与审核机制

LLM 按 JSON 结构返回实体、关系和规则候选项，每一候选项包含置信度和证据片段。系统以确定性方式校验 JSON 结构、受控关系类型及证据片段与来源条文的精确匹配。通过基础格式校验的输出以待审核标注形式保存。审核人员在阅读来源条文后可接受、拒绝或修订候选项；只有被接受的信息才写入知识图谱。论文将完整报告模型标识、访问日期、提示词版本、温度、输出上限和重试策略。

### 3.4 合规审查与不确定性状态

项目数据以结构化参数形式保存。只有在规则的适用条件和所需项目输入均可获得时，系统才对已审核规则执行判断。`pass` 表示完整项目输入满足适用且可计算的规则；`fail` 表示完整项目输入违反该规则。对于项目条件缺失、规则语义不完整或证据不可获得的情形，系统输出 `pending`。`advisory` 用于表示已审核但未触发的规则，或需要专业人员注意而不宜给出二元合规结论的事项。每一项输出均保留项目输入、期望值、解释、关联条文和运行标识。

## 4 数据集与实验设计

主实验语料由 320 条条文构成，包括全部 67 条已导入 GB50011 条文，以及按照条文首级章节、以随机种子 20260624 分层抽取的 253 条 GB50016 条文。预实验语料包括 40 条 GB50096 条文和 40 条 GB55019 条文，不参与主实验结果计算。

两名标注人员独立标注实体、关系、规则、适用条件及连续证据片段，第三名审核者对分歧进行裁决。裁决前先计算一致性；若相关一致性指标低于 0.70，则修订标注指南并重新标注存在争议的类别。经裁决后的语料是抽取性能评价唯一可用的金标准。

本文比较三类方法：模式规则基线、无证据约束的 LLM JSON 抽取，以及本文提出的受证据约束 LLM 抽取方法。针对实体、关系和规则分别计算精确率、召回率和 F1 值。证据可定位率定义为输出项目所引用文本能够作为连续片段在来源条文中找到的比例。结果将按规范分别报告，并给出宏平均和 95% Bootstrap 置信区间。

合规审查层采用 32 个参数化场景，覆盖通过、不满足、待确认和提示四种状态。当前案例集用于确认软件实现行为，是回归测试集。在论文发表前，应由独立领域专家审核每一个案例；若案例的预期结果无法由其引用条文合理支持，则应删除或修订。审查指标包括准确率、宏平均 F1 值、关联条文可定位率和不当确定性率；其中，不当确定性率指专家参考状态应为 `pending` 的案例被系统输出为 `pass` 或 `fail` 的比例。

## 6 讨论与有效性威胁

本框架旨在辅助专业判断，而非替代注册建筑师、结构工程师或法定规范审查。条文证据追溯能够限制无依据的输出，但无法独立解决规范版本效力、跨条文交互、适用范围冲突和专业解释等问题。当前语料仅覆盖部分中国建筑规范，其规则分布不一定代表其他规范体系。LLM 输出还可能随模型更新而发生变化，因此记录模型元数据、提示词和原始输出是必要条件，但不能保证未来完全复现。最后，即使图谱经过审核，也可能遗漏相关规则；因此，`pending` 应被理解为经过校准的不确定性表达，而非需要被消除的系统缺陷。

## 7 结论

本文提出一种面向建筑规范的可追溯知识图谱与合规审查框架，用于将规范条文转化为可审核的图谱知识，并基于该知识执行不确定性感知的项目审查。其核心设计在于：将每个候选知识断言绑定到连续来源条文片段，并在写入图谱前实施人工审核。后续完成的实验将量化该机制对抽取质量、审计能力、审核工作量和审查结论校准性的影响。未来研究可将经审核规则与 BIM 参数连接，扩展规范版本对比，并开展跨地区、跨规范体系的迁移评估。
